# Логирование данных для создания Order в БД

## Задача
Реализовать логирование всех собранных данных для создания Order в БД при нажатии кнопки "Завершить поездку" в консоль браузера.

## Выполненные изменения

### 1. Улучшено логирование в MapPage.tsx

Добавлено подробное логирование в три ключевые функции:

#### Функция `handleCreateOrder()` - создание заказа
- Добавлено логирование времени события
- Добавлено логирование общих данных (carId, rideCost, distanceKm, destLocation)
- Добавлено логирование данных пользователя (userId, email, verified)
- Добавлено логирование данных автомобиля (carId, carStatus, carModel, carManufacture, coefficient, fuelLevel, location)
- Добавлено логирование данных поездки (distanceKm, rideCost, destLocation)
- Добавлено логирование данных для запроса к бэкенду (endpoint, method, payload)

#### Функция `handleEndOrder()` - завершение заказа
- Добавлено логирование времени события
- Добавлено логирование общих данных (orderId, orderStatus, carId, price, distanceKm, destLat, destLng, fuelConsumed)
- Добавлено логирование данных пользователя (userId, email, verified)
- Добавлено логирование данных автомобиля (carId, carStatus, fuelLevel)
- Добавлено логирование данных поездки (orderId, distanceKm, fuelConsumed, startLocation, endLocation, price, status)
- Добавлено логирование данных для запроса к бэкенду (endpoint, method, payload)

#### Функция `handleEndRideFromMap()` - завершение поездки без заказа
- Добавлено логирование времени события
- Добавлено логирование общих данных (наличие активного заказа, ID заказа, статус заказа, ID автомобиля, статус автомобиля, наличие точки назначения, расстояние)
- Добавлено логирование данных пользователя (userId, email, verified)
- Добавлено логирование данных автомобиля (carId, carStatus, carModel, carManufacture, coefficient, fuelLevel, currentLocation)
- Добавлено логирование данных маршрута (destLat, destLng, distanceKm, rideCost)

### 2. Исправлены ошибки компиляции

#### Исправлены ошибки в RideCostCalculator.tsx
- Добавлена обработка возможных `undefined` значений для полей `baseRate`, `coefficient`, `discountPercent`, `distanceKm`
- Использованы значения по умолчанию (`|| 0`) для безопасного отображения

#### Исправлены ошибки в MapPage.tsx
- Улучшена обработка ответа от `/api/user/orders/active` - теперь правильно обрабатывается случай, когда заказа нет (возвращается `null`)
- Добавлены проверки существования маркеров и маршрутов на карте перед удалением с использованием `map.hasLayer()`
- Исправлена обработка ошибок в leaflet-routing-machine для предотвращения "Cannot read properties of null (reading 'removeLayer')"

### 3. Создан тестовый файл для демонстрации логирования

Создан файл `test-logging.html`, который демонстрирует:
- Как выглядит логирование при создании заказа
- Как выглядит логирование при завершении заказа с данными маршрута
- Как выглядит логирование при завершении поездки без активного заказа

## Как проверить работу

1. Откройте файл `test-logging.html` в браузере
2. Нажмите кнопки "Test Create Order Logging", "Test End Order Logging", "Test End Ride Logging"
3. Откройте консоль разработчика (F12) и перейдите на вкладку Console
4. Убедитесь, что данные логируются в консоль браузера

## Структура логирования

Каждое логирование включает:
1. **Заголовок** с указанием типа операции
2. **Время** события в формате ISO
3. **Общая информация** о состоянии системы
4. **Данные пользователя** (userId, email, verified)
5. **Данные автомобиля** (carId, carStatus, технические характеристики)
6. **Данные поездки/маршрута** (distanceKm, rideCost, координаты)
7. **Данные для запроса к бэкенду** (endpoint, method, payload)
8. **Разделитель** конца данных

## Результат

Теперь при нажатии кнопки "Завершить поездку" в консоль браузера отправляются все собранные данные для создания Order в БД, что позволяет:
- Отлаживать процесс создания заказа
- Проверять корректность собранных данных
- Анализировать проблемы при создании заказа
- Визуализировать поток данных между фронтендом и бэкендом
