# Улучшения функционала после поездки

## Завершенные задачи

### 1. Изменение локации автомобиля после поездки
**Цель:** После завершения поездки автомобиль перемещается в последнюю точку маршрута.

#### Реализованные изменения:

**Бэкенд:**
1. **Новый DTO:** `EndOrderWithLocationRequest` с полями `newLocationX` и `newLocationY`
2. **Новый метод в OrderService:** `endOrderWithLocation()` для завершения заказа с обновлением локации
3. **Новый эндпоинт:** `PUT /api/orders/{orderId}/end-with-location`
4. **Обновление OrderServiceImpl:** 
   - Обновление локации автомобиля при завершении заказа
   - Расчет расхода топлива (20% за 100 км пропорционально)
   - Обновление уровня топлива автомобиля

**Фронтенд:**
1. **Обновленный API клиент:** Добавлена функция `endOrderWithLocation()`
2. **Обновление MapPage.tsx:** 
   - Функция `handleEndOrder` теперь передает координаты точки назначения
   - Расчет расхода топлива на фронтенде для отображения
   - Обновление локального состояния автомобиля с новой локацией и топливом

#### Логика работы:
1. При завершении заказа передаются координаты точки назначения (`destLat`, `destLng`)
2. Сервер обновляет локацию автомобиля на эти координаты
3. Рассчитывается расход топлива: 20% за каждые 100 км пропорционально
4. Уровень топлива уменьшается на рассчитанное значение
5. Автомобиль возвращается в статус `AVAILABLE` с новой локацией

### 2. Уменьшение процента топлива на 1/5 (20%) за 100 км пропорционально
**Цель:** Реалистичное потребление топлива в зависимости от пройденного расстояния.

#### Реализованные изменения:

**Формула расчета:**
```
fuelConsumptionPer100Km = 20.0 // 20% за 100 км
fuelConsumed = (distanceKm / 100.0) * fuelConsumptionPer100Km
newFuelLevel = Math.max(0, currentFuelLevel - fuelConsumed)
```

**Реализация:**
1. **Бэкенд:** Расчет в `OrderServiceImpl.endOrderWithLocation()`
2. **Фронтенд:** Расчет в `MapPage.tsx` для отображения изменений
3. **Ограничение:** Уровень топлива не может быть отрицательным (`Math.max(0, ...)`)

#### Примеры:
- **10 км:** `(10 / 100) * 20 = 2%` расхода
- **50 км:** `(50 / 100) * 20 = 10%` расхода  
- **100 км:** `(100 / 100) * 20 = 20%` расхода
- **250 км:** `(250 / 100) * 20 = 50%` расхода

### 3. Просмотр своих поездок в профиле
**Цель:** Пользователи могут просматривать историю своих поездок в профиле.

#### Реализованные изменения:

**Бэкенд:**
1. **Новый контроллер:** `UserOrdersController` с эндпоинтами:
   - `GET /api/user/orders/my-orders` - все заказы пользователя
   - `GET /api/user/orders/active` - активный заказ пользователя
2. **Новые методы в OrderService:**
   - `getUserOrders(Long userId)` - все заказы пользователя
   - `getActiveOrder(Long userId)` - активный заказ (статус STARTED)
3. **Обновление OrderServiceImpl:** Реализация методов через репозиторий

**Фронтенд:**
1. **Новый API клиент:** `userOrders.api.ts` с функциями:
   - `getUserOrders(token)` - получение всех поездок
   - `getActiveOrder(token)` - получение активного заказа
2. **Новый компонент:** `UserTrips.tsx` для отображения истории поездок
3. **Интеграция в профиль:** Компонент добавлен в `ProfilePage.tsx`
4. **Обновление MapPage.tsx:** Использование нового эндпоинта для активного заказа

#### Функционал компонента UserTrips:
- **Загрузка данных:** Автоматическая загрузка при монтировании
- **Форматирование:** Даты, валюты, расстояния
- **Статусы:** Визуальное отображение статусов поездок
- **Детали:** Отображение расхода топлива, скидок, оценок
- **Адаптивность:** Поддержка мобильных устройств
- **Обработка ошибок:** Сообщения об ошибках загрузки

## Тестирование функционала

### Сценарии использования:

#### 1. Завершение поездки с обновлением локации:
```
1. Выберите автомобиль и постройте маршрут
2. Создайте заказ
3. Завершите заказ
4. Наблюдайте:
   - Автомобиль перемещается в точку назначения
   - Уровень топлива уменьшается пропорционально расстоянию
   - Статус автомобиля возвращается в AVAILABLE
```

#### 2. Просмотр истории поездок:
```
1. Откройте профиль (/profile)
2. Перейдите в раздел "История поездок"
3. Наблюдайте:
   - Список всех завершенных поездок
   - Детали каждой поездки (дата, расстояние, стоимость)
   - Статусы поездок (В процессе/Завершена)
```

#### 3. Активный заказ:
```
1. Начните поездку (статус IN_USE)
2. Откройте страницу карты
3. Наблюдайте:
   - Показывается только ваш автомобиль
   - Кнопка "Закончить поездку" доступна
   - В профиле отображается активная поездка
```

### Обработка ошибок:

#### 1. Нет точки назначения:
- Сообщение: "Недостаточно данных для завершения заказа"
- Требуется построить маршрут перед завершением

#### 2. Ошибка расчета топлива:
- Автоматический расчет на фронтенде и бэкенде
- Защита от отрицательных значений (`Math.max(0, ...)`)

#### 3. Ошибка загрузки поездок:
- Сообщение об ошибке в компоненте
- Возможность повторной загрузки
- Graceful degradation
