# API управления заказами

## Эндпоинты

### 1. Создание заказа
`POST /api/orders/create`

### 2. Завершение заказа
`PUT /api/orders/{orderId}/end`

## Общие требования к авторизации
- Пользователь должен быть авторизован (передать токен в заголовке `Authorization: Bearer <token>`)
- Пользователь должен быть верифицирован (`verified: true`)
- Пользователь не должен быть заблокирован (`blocked: false`)

## Создание заказа

### Заголовки
```
Authorization: Bearer <jwt-token>
Content-Type: application/json
```

### Тело запроса (JSON)
```json
{
  "carId": 1,
  "price": 60.0
}
```

### Поля запроса
| Поле | Тип | Обязательно | Описание |
|------|-----|-------------|----------|
| carId | Long | Да | ID автомобиля |
| price | Double | Да | Предварительная стоимость поездки |

### Успешный ответ (200 OK)
```json
{
  "orderId": 1,
  "userId": 123,
  "carId": 1,
  "startTime": "2024-01-15T10:30:00",
  "endTime": null,
  "status": "STARTED",
  "distance": null,
  "spendFuel": null,
  "price": 60.0,
  "discount": 0.0,
  "ratingEdits": 0.0
}
```

### Логика создания заказа
1. Проверяется доступность автомобиля (статус должен быть `AVAILABLE`)
2. Создается запись в таблице `orders` со статусом `STARTED`
3. Устанавливается `startTime = текущее время`
4. Устанавливается переданная цена `price`
5. Обновляется статус автомобиля на `IN_USE`

## Завершение заказа

### Заголовки
```
Authorization: Bearer <jwt-token>
Content-Type: application/json
```

### Тело запроса (JSON)
```json
{
  "distanceKm": 15.0,
  "spendFuel": 2.5
}
```

### Поля запроса
| Поле | Тип | Обязательно | Описание |
|------|-----|-------------|----------|
| distanceKm | Double | Да | Пройденное расстояние в км |
| spendFuel | Double | Нет | Потраченное топливо в литрах |

### Успешный ответ (200 OK)
```json
{
  "orderId": 1,
  "userId": 123,
  "carId": 1,
  "startTime": "2024-01-15T10:30:00",
  "endTime": "2024-01-15T11:30:00",
  "status": "COMPLETED",
  "distance": 15.0,
  "spendFuel": 2.5,
  "price": 60.0,
  "discount": 0.0,
  "ratingEdits": 0.0
}
```

### Логика завершения заказа
1. Проверяется существование заказа
2. Проверяется, что заказ еще не завершен (статус не `COMPLETED`, `endTime` не установлен)
3. Устанавливается `endTime = текущее время`
4. Обновляется статус на `COMPLETED`
5. Записываются `distance` и `spendFuel`
6. Обновляется статус автомобиля на `AVAILABLE`

## Ошибки

### 400 Bad Request
```json
{
  "message": "Некорректный запрос"
}
```
Причины:
- Неверный формат JSON
- Отсутствуют обязательные поля
- Некорректные значения полей

### 401 Unauthorized / 403 Forbidden
```json
{
  "message": "Недостаточно прав"
}
```
Причины:
- Отсутствует заголовок Authorization
- Неверный формат токена
- Пользователь заблокирован (`blocked: true`)
- Пользователь не верифицирован (`verified: false`)

### 404 Not Found
```json
{
  "message": "Заказ не найден"
}
```
Причины:
- Заказ с указанным `orderId` не существует (для завершения заказа)
- Автомобиль с указанным `carId` не существует (для создания заказа)

### 409 Conflict
```json
{
  "message": "Автомобиль не доступен"
}
```
Причины:
- Автомобиль не в статусе `AVAILABLE` (статус `BOOKED`, `IN_USE`, `OUT_OF_SERVICE`)

### 422 Unprocessable Entity
```json
{
  "message": "Заказ уже завершен"
}
```
Причины:
- Попытка завершить уже завершенный заказ (статус `COMPLETED`)

### 500 Internal Server Error
```json
{
  "message": "Внутренняя ошибка сервера"
}
```
Другие внутренние ошибки сервера.

## Интеграция с другими системами

### Связь с расчетом стоимости
1. Сначала рассчитывается стоимость через `POST /api/ride-cost/calculate`
2. Полученная стоимость передается в `price` при создании заказа
3. При завершении можно пересчитать стоимость на основе фактического расстояния

### Связь с автомобилями
- При создании заказа: `CarStatus.AVAILABLE` → `CarStatus.IN_USE`
- При завершении заказа: `CarStatus.IN_USE` → `CarStatus.AVAILABLE`

### Связь с пользователями
- Только авторизованные, верифицированные, не заблокированные пользователи могут создавать заказы
- Заказ привязывается к пользователю через `user_id`

## Безопасность

### Проверки при создании заказа:
1. Авторизация пользователя
2. Верификация пользователя
3. Статус пользо��ателя (не заблокирован)
4. Доступность автомобиля

### Проверки при завершении заказа:
1. Авторизация пользователя
2. Верификация пользователя
3. Статус пользователя (не заблокирован)
4. Существование заказа
5. Статус заказа (не завершен)

## Тестирование

### Валидные сценарии:
1. Создание заказа с доступным автомобилем
2. Завершение незавершенного заказа
3. Корректные значения расстояния и топлива

### Невалидные сценарии:
1. Создание заказа с недоступным автомобилем → 409
2. Завершение несуществующего заказа → 404
3. Завершение уже завершенного заказа → 422
4. Отсутствие авторизации → 401/403
5. Заблокированный пользователь → 403
6. Неверифицированный пользователь → 403
