# Реализация функционала бронирования автомобилей и управления статусами

## Завершенные задачи

### 1. API для управления статусами автомобилей
**Файл:** `frontend/src/api/car.api.ts`

#### Реализованные функции:
- `updateCarStatus(carId, status, token)` - общее обновление статуса автомобиля
- `bookCar(carId, token)` - бронирование автомобиля (статус → BOOKED)
- `startRide(carId, token)` - начало поездки (статус → IN_USE)
- `endRide(carId, token)` - завершение поездки (статус → AVAILABLE)

#### Интеграция с бэкендом:
- Использует существующий эндпоинт `PUT /api/cars/{id}/status`
- Поддерживает все статусы: `AVAILABLE`, `BOOKED`, `IN_USE`, `OUT_OF_SERVICE`
- Проверка авторизации через JWT токен

### 2. Обновление кнопки "Забронировать"
**Файл:** `frontend/src/pages/MapPage.tsx`

#### Реализованный функционал:
- **Реальное бронирование:** Кнопка "Забронировать" теперь вызывает API для изменения статуса автомобиля
- **Валидация:** Проверка авторизации, верификации и доступности автомобиля
- **Обновление UI:** Автоматическое обновление списка автомобилей и маркеров на карте
- **Обработка ошибок:** Понятные сообщения об ошибках для пользователя

#### Логика бронирования:
1. Проверка авторизации и верификации пользователя
2. Проверка доступности автомобиля (статус должен быть AVAILABLE)
3. Вызов API `bookCar` для изменения статуса на BOOKED
4. Обновление локального состояния автомобилей
5. Обновление маркеров на карте

### 3. Добавление кнопки "В путь"
**Файл:** `frontend/src/pages/MapPage.tsx`

#### Реализованный функционал:
- **Начало поездки:** Кнопка "В путь" появляется для забронированных автомобилей
- **Изменение статуса:** Переводит автомобиль из статуса BOOKED в IN_USE
- **Валидация:** Проверка, что автомобиль действительно забронирован
- **Интеграция:** Использует API `startRide` для обновления статуса

#### Логика начала поездки:
1. Проверка авторизации и верификации пользователя
2. Проверка статуса автомобиля (должен быть BOOKED)
3. Вызов API `startRide` для изменения статуса на IN_USE
4. Обновление локального состояния автомобилей
5. Обновление маркеров на карте

### 6. Интеграция с существующей системой

#### Связь с другими компонентами:
1. **Аутентификация:** Использует существующую систему JWT через `authApi.getAccessToken()`
2. **Проверка статуса:** Интеграция с `useAuth` для проверки `user.verified`
3. **Обновление маркеров:** Автоматическое обновление маркеров на карте при изменении статуса
4. **Синхронизация данных:** Локальное состояние синхронизируется с сервером

#### Безопасность:
- Все запросы требуют авторизации через JWT токен
- Проверка верификации пользователя перед бронированием
- Валидация статусов на клиенте и сервере

## Тестирование функционала

### Сценарии использования:

#### 1. Бронирование автомобиля:
```
1. Авторизуйтесь и пройдите верификацию
2. Выберите доступный автомобиль (статус AVAILABLE)
3. Нажмите "Забронировать"
4. Наблюдайте:
   - Статус автомобиля меняется на BOOKED
   - Маркер на карте становится оранжевым
   - Кнопка "Забронировать" заменяется на "В путь"
```

#### 2. Начало поездки:
```
1. Убедитесь, что автомобиль забронирован (статус BOOKED)
2. Нажмите "В путь"
3. Наблюдайте:
   - Статус автомобиля меняется на IN_USE
   - Маркер на карте становится синим
   - Появляется сообщение "Автомобиль в поездке"
```

#### 3. Завершение поездки:
```
1. Постройте маршрут и рассчитайте стоимость
2. Создайте заказ (автомобиль перейдет в IN_USE)
3. Завершите заказ
4. Наблюдайте:
   - Статус автомобиля возвращается в AVAILABLE
   - Маркер на карте становится зеленым
   - Маршрут очищается
```

### Обработка ошибок:

#### 1. Нет авторизации:
- Сообщение: "Требуется авторизация и верификация для бронирования"
- Кнопка неактивна или скрыта

#### 2. Автомобиль недоступен:
- Сообщение: "Автомобиль недоступен для бронирования"
- Кнопка "Забронировать" не отображается

#### 3. Ошибка API:
- Сообщение: "Ошибка бронирования автомобиля: [детали ошибки]"
- Сохранение предыдущего состояния
